## 1. 测试方法

`tests/audit_live.py` 启动两个独立官方 Zenoh 订阅，不依赖网关计数；生成 Protobuf 解析，Pillow 对每个 JPEG 执行 load()，逐帧检查Array/format/尺寸/SOI/EOI/seq/stamp。并行订阅实际 Foxglove WebSocket，使用其公布的 Protobuf descriptor 解码。

频率=(N-1)/(末次接收monotonic时刻-首次)，间隔分位数用线性插值。两订阅先后建立，会有边界帧差异；内容比对排除起止各1秒，不能把订阅边界差异当丢包。Foxglove标准schema没有原协议seq/scaler/Array，这些字段在直接订阅通道检查，WS统计中的0不表示其也独立验证了这些不存在的字段。

## 5. 复现命令

在项目根目录：

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_gateway -v
.\.venv\Scripts\python.exe -m tests.test_recovery
.\.venv\Scripts\python.exe -m tests.audit_live --seconds 220 --output evidence/manual-220s
.\.venv\Scripts\python.exe -m tests.audit_commands
```

220秒通常够点云1000帧，但若源频率降低，应以输出JSON帧数判断是否到达，不能以时间猜。audit_commands会占用板端共享seq，不能在丢帧频率测试同时运行。`tests/audit_supervisor.ps1` 会主动中断本机画面以测重启，只在维护窗口运行。

audit_live 输出测量而非自动整协议合格证；即使进程退出0也必须检查错误计数/样本数/WS错误/比较结果。输出目录必须是新目录，避免覆盖旧证据。

未来恢复30分钟测试时，使用 `--seconds 1802 --output evidence/<新的目录>`，并完成物理热插拔、频率阈值/容差确认后重新签字。当前不继续后台运行该测试。
