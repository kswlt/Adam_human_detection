# 交付范围与验收依据

依据：项目原件《2-空间相机通信协议V1.0.pdf》，用户补充的原生 JPEG、1080p 优先、全量点云、Foxglove 双画面、稳定性与项目精简要求。

## 必须验证

| 项目 | 验收证据 |
| --- | --- |
| Foxglove 同时显示相机与点云 | 本机应用双面板实际画面、两路 WebSocket 收包与解码 |
| 点云来自协议 Zenoh 通道 | 直接订阅 active/{sn}/pointcloud；不以 UDP 旁路代替协议验收 |
| 不抽稀点云 | 每个收到的 LidarPoint 均进入显示消息，数量逐帧核对 |
| 原生 JPEG | MC800S snapshot -> HTTP -> ImageMsgArray，JPEG 字节不转码、不修改 |
| 图像字段 | array 长度 1、format=2、实际尺寸、完整 SOI/EOI、可解码 |
| 接收质量 | 已做 100 帧、1000 帧；30 分钟按用户 2026-08-31 最新要求暂缓。统计平均 Hz、P50/P95/P99/最大间隔、序号、时间戳、解析与解码错误 |
| 稳定性 | 不用重复旧图伪造帧率；显示陈旧状态；恢复时间实测 |
| 协议审查 | SN、所有 topic/Array、缩放、帧头、setting/reboot/config_file、配置、QoS、发现与 router |
| 恢复机制 | 进程退出、服务中断、连接恢复；物理拔插必须与模拟中断区分 |
| 文档 | 项目说明、构建部署、运行维护、协议矩阵、验收方法与真实结果、改动与限制 |
| 清理 | 删除可再生/确认不用的历史产物；保留源码、依赖许可证、协议原件、验收证据和回滚包 |

## 不得混淆

- IMU 按用户此前要求不修改；仍列出审查结果，未验收不能写为通过。
- 协议 1080p 出现在带宽估算，不是独立硬性尺寸字段；用户的 1080p 优先要求仍有效，不自动降分辨率。
- stream=0 的实测 720x480 不是 720p（1280x720）；旧报告的“720p”名称必须更正。
- setting 的文字规定是持久化、重启生效，不能仅因未实时生效判定失败。
- setting.image_format 的第 6 节与第 8 节注释互相冲突，需记录歧义，不擅自声称协议已明确。
- ring、offset 及 RGB 是否可获得需核对设备；字段存在不等于数据语义完整。
- 审查的交付可以明确“不符合/未验证”，不可将存在缺项的系统写成全面通过。
